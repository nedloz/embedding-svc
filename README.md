# embedding-svc — сервис векторных представлений

## Модель

Сейчас сервис работает на `intfloat/multilingual-e5-base` (768 измерений, многоязычная, требует
префиксов `query: ` / `passage: ` — их ставит сервис по полю `kind`). Ниже — история выбора
bge-m3 вместо англоязычной модели; размерности `VECTOR(1024)` и 768 различаются, смена модели
требует миграции схемы и переиндексации.

## Почему BAAI/bge-m3, а не англоязычная модель

Изначально здесь стояла `mixedbread-ai/mxbai-embed-large-v1`. Её токенизатор — `BertTokenizer`
со словарём на 30 522 элемента, собранным по английскому корпусу. Русских подслов в нём
практически нет, поэтому токенизатор дробил русские слова до отдельных букв:

```
промежуточной → ['п','##р','##о','##м','##е','##ж','##у','##т','##о','##ч','##н','##о','##и']
assessment    → ['assessment']
```

Измерено на корпусе проекта: **1.14 символа на токен** для русского против 6.91 для
английского. Следствий два. Во-первых, окно модели в 512 токенов покрывало около 600 символов,
а чанкер выдавал в среднем 5854 — `sentence-transformers` молча обрезал вход, и в вектор
попадала примерно десятая часть чанка. Ошибки при этом не возникало: вектор нужной размерности
возвращался, счётчики чанков и эмбеддингов сходились один в один. Во-вторых, даже уместившийся
текст модель разбирала как последовательность букв, а не слов.

`BAAI/bge-m3` решает обе проблемы: словарь XLM-RoBERTa на 250 002 элемента (`обучающихся` —
один токен), **6.15 символа на токен** для русского, окно 8192 токена. Размерность у обеих
моделей 1024, поэтому `VECTOR(1024)` в схеме БД остаётся без изменений.

Однофайловый FastAPI-сервис поверх `sentence-transformers`. Считает эмбеддинги текстов и
отдаёт их по HTTP.

> **Критическая зависимость всей системы.** С момента перевода `ingest-worker` на этот сервис
> он является **единственным источником эмбеддингов**: через него проходят и векторы чанков
> при индексации, и векторы вопросов при поиске, и векторы имён сущностей графа. Если модель
> здесь заменить — все ранее посчитанные векторы становятся несравнимыми, и требуется полная
> переиндексация чанков и пересборка графа (см. README `graph-rag-svc`, §13.1).

## Роль в архитектуре

```
ingest-worker  ──┐
                 ├──► embedding-svc  ──►  sentence-transformers (GPU/CPU)
graph-rag-svc  ──┘        │
                          └─ модель загружается один раз, в фоне после старта процесса
```

Потребители: `ingest-worker` (векторы чанков при индексации) и `graph-rag-svc` (векторы
вопросов для поиска и векторы имён сущностей для резолюции). Собственную модель они больше
не грузят — именно ради того, чтобы модель и размерность были объявлены в одном месте.

Сервис не имеет базы данных и не хранит состояние: он stateless, кроме загруженной в память
модели.

## API

Все эндпоинты, кроме `/ping` и `/health`, требуют межсервисной аутентификации.

Модель грузится в фоновом потоке после старта процесса. Пока она не загружена, `/ping` и
`/embed` отвечают `503` с причиной (номер попытки и последняя ошибка), `/health` — `200`.

### `POST /embed`

```jsonc
// запрос
{ "texts": ["первый текст", "второй текст"], "normalize": true, "kind": "passage" }

// ответ
{
  "model": "intfloat/multilingual-e5-base",
  "dimension": 768,
  "embeddings": [[0.01, -0.02, ...], [...]]
}
```

`kind` — `passage` (по умолчанию, документы индекса) или `query` (поисковый запрос); иное → `422`.
Для моделей семейства e5 (в имени есть `e5`) сервис сам добавляет к текстам префикс
`passage: ` / `query: `, для остальных моделей тексты не меняются. Лимиты длины считаются
по исходным текстам, без префикса.

`normalize: true` (по умолчанию) возвращает нормированные векторы — на них корректно
считается косинусная близость. Потребители полагаются на это поведение.

### `GET /ping`

```jsonc
{ "status": "ok", "model": "intfloat/multilingual-e5-base", "dimension": 768, "device": "cuda", "cuda_available": true }
```

Readiness-проверка: `503`, пока модель не загружена, `200` с размерностью — после. На неё
опирается healthcheck в `main/docker-compose.yml`. Потребители вызывают её **при запуске** для
сверки размерности модели с фактическим типом колонок в БД: при расхождении они отказываются
стартовать, а на `503` повторяют запрос. Аутентификации не требует.

### `GET /health`

```jsonc
{ "status": "loading", "model": "intfloat/multilingual-e5-base", "attempts": 3, "last_error": "OSError: ..." }
```

Liveness: `200`, пока процесс жив, — и во время загрузки модели, и при её сбоях. Нужен для
диагностики: «процесс работает, но модель не грузится, и вот почему». Аутентификации не требует.

### Межсервисная аутентификация

Статических токенов нет. Вызывающего подтверждает клиентский сертификат, а прокси-сайдкар
передаёт имя из него в `X-Caller-Identity` (`main/infra/mtls`). Заголовку верят только от
loopback; запрос с другого адреса или без заголовка → `403`. `INTERNAL_AUTH_MODE=insecure`
отключает проверку (только для отладки без PKI).

## Переменные окружения

| Переменная | По умолчанию | Описание |
| :-- | :-- | :-- |
| `EMBEDDER_MODEL_NAME` | `intfloat/multilingual-e5-base` | Модель sentence-transformers. **Смена = переиндексация всего** |
| `SERVICE_NAME` | `embedding-svc` | Собственное имя сервиса |
| `INTERNAL_AUTH_MODE` | `mtls` | `mtls` — верить `X-Caller-Identity` только от loopback; `insecure` — без проверки (отладка) |
| `MAX_TEXTS_PER_REQUEST` | `256` | Максимум текстов в одном `/embed`; превышение → `413` |
| `MAX_TEXT_CHARS` | `20000` | Максимальная длина одного текста |
| `MAX_TOTAL_CHARS` | `1000000` | Максимальная суммарная длина текстов в запросе |
| `MODEL_LOAD_RETRY_WAIT_SEC` | `5` | Пауза перед повтором после неудачной загрузки модели; удваивается с каждой попыткой |
| `MODEL_LOAD_RETRY_MAX_WAIT_SEC` | `300` | Верхняя граница этой паузы |

Размерность модели (`EMBEDDING_DIM`) объявляется **не здесь**, а в корневом `main/.env` —
она общая для БД и всех потребителей.

## Технические проблемы и ограничения

Раздел собран аудитом кода; ранее README у сервиса не было.

### Высокий приоритет

1. ~~**Нет ограничения на размер запроса.**~~ **Исправлено.** Поле `texts` было списком
   произвольной длины, и один запрос с десятками тысяч текстов исчерпал бы память,
   остановив заодно индексацию и поиск. Добавлены лимиты `MAX_TEXTS_PER_REQUEST`,
   `MAX_TEXT_CHARS` и `MAX_TOTAL_CHARS`; превышение — `413`, а не падение процесса.
   Парная правка: `ingest-worker` теперь режет чанки документа на батчи
   (`EMBED_BATCH_SIZE=64`) — раньше он отправлял все чанки одним запросом, и лимиты
   сломали бы индексацию.
2. ~~**Модель загружается на уровне модуля, при импорте.**~~ **Исправлено.** Если загрузка
   падала (нет сети, нет места, недоступен GPU), исключение поднималось при импорте, процесс
   падал и контейнер уходил в цикл перезапусков; пока модель грузилась, сервис не отвечал
   вообще. Теперь модель грузится в фоновом потоке после старта процесса и при сбое
   повторяется с растущей паузой (`MODEL_LOAD_RETRY_WAIT_SEC` → `MODEL_LOAD_RETRY_MAX_WAIT_SEC`).
   Разделены liveness (`/health`, всегда `200`) и readiness (`/ping`, `503` до загрузки);
   `/embed` до загрузки тоже отвечает `503`. Ошибка загрузки видна в логе и в ответах, а не
   теряется между рестартами.
3. ~~**Нет healthcheck в compose, а зависимые сервисы стартуют по `service_started`.**~~
   **Исправлено.** Потребители поднимались раньше, чем модель загружена, и держались только
   на собственных повторах. Теперь у `embedding-svc` healthcheck на `/ping`, а `graph-rag-svc`
   и `ingest-worker` зависят от него по `service_healthy`. Их повторы опроса `/ping` оставлены
   как страховка на случай перезапуска `embedding-svc` отдельно от них.
4. ~~**Ошибка в `TRUSTED_SERVICE_TOKENS` молча запрещает всё.**~~ (Токены позже удалены вовсе.) **Исправлено.** JSON
   парсился на каждый запрос, а ошибка разбора превращалась в пустой словарь, из-за чего все
   вызовы получали `403` без указания на настоящую причину. Теперь разбор выполняется один
   раз при запуске: некорректный JSON роняет сервис с внятным сообщением, а пустой словарь
   при включённой аутентификации пишет предупреждение в лог.

### Средний приоритет

5. **Нет ограничения параллелизма.** `model.encode` — блокирующий вызов; FastAPI выполняет
   синхронный эндпоинт в общем threadpool, поэтому несколько крупных запросов конкурируют
   за GPU без какой-либо очереди и без backpressure.
6. **Дублирование проверки аутентификации.** `embed()` объявляет заголовки как параметры и
   *дополнительно* вызывает `verify_internal_request(...)` вручную; `Header(...)` внутри самой
   функции-зависимости при этом не используется. Работает, но запутывает.
7. **Жёсткая привязка к NVIDIA в compose.** Блок `deploy.resources.reservations.devices`
   с драйвером `nvidia` не даст поднять сервис на машине без nvidia-runtime, хотя код
   корректно откатывается на CPU (`DEVICE = "cuda" if torch.cuda.is_available() else "cpu"`).
8. **Нет метрик и трассировки.** Непонятно, сколько времени занимает эмбеддинг и какой
   потребитель создаёт нагрузку.

### Замечание по эксплуатации

Модель кешируется в volume `hf_cache` (`/app/.cache/huggingface`). При первом запуске на
чистом окружении сервис скачивает веса — это может занять заметное время; потребители в этот
момент ждут, пока healthcheck не станет `healthy` (`start_period: 900s` в compose рассчитан на
это скачивание). Если на медленном канале не хватает и его — увеличьте `start_period`.

## Метрики

`GET /metrics` отдаёт Prometheus (за mTLS - только пользователю `prometheus`, политика в `infra/mtls/embedding-svc.conf`). Кроме HTTP-метрик (`http_requests_total`, `http_request_duration_seconds`, `http_requests_inprogress`; метка `handler` - шаблон маршрута) сервис отдаёт бизнес-метрики с префиксом `pochemuchnik_`. Код: `app/metrics.py`, тесты: `tests/`. Общая картина и дашборды - `infra/observability/README.md` в корневом репозитории.

| Метрика | Что считает |
| :-- | :-- |
| `embed_requests_total` | принятые запросы `/embed` (не отклонённые по размеру) |
| `embed_batch_size` | число текстов в запросе |
| `embed_duration_seconds` | время кодирования моделью |
